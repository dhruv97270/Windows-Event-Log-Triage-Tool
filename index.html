Windows Security Event Log Triage Tool

Learn how analysts read Windows security events.

Export events from Windows Event Viewer as CSV and drop them in. The tool recognises the Event IDs that matter, links related events together, and explains each finding: what happened, why it may deserve investigation, what innocent reasons could explain it, and what to check next.

Your Windows security logs are analysed locally in your browser. Files are not uploaded or transmitted anywhere. There are no servers, analytics, cookies or tracking, and the page is technically blocked from making network requests.

Educational SOC triage tool. Findings indicate activity that may deserve investigation and do not prove malicious behaviour. Only analyse logs from systems you own or are authorised to investigate.

          How to Think Like a SOC Analyst

          One security event rarely tells the entire story. Analysts build context by correlating multiple events.

          1. Identify the event. Which Event ID is it, and which log did it come from?
          2. Understand what happened. Read the description in plain words: a logon, a failure, a group change.
          3. Identify the affected user or system. Which account, which computer, which source IP?
          4. Determine whether the activity is expected. Is this person in IT? Is it their normal working time and device?
          5. Look for related events. What happened just before and just after, for the same account or source?
          6. Correlate authentication and privilege activity. Failures followed by success, or a new account that quickly gains admin rights, tell a bigger story than either event alone.
          7. Gather additional evidence. Tickets, change requests, EDR, VPN, MFA and other servers' logs.
          8. Decide whether escalation is required. Close it as benign, keep watching, or escalate to incident response.

          A detection is a reason to investigate

          A detection is a reason to investigate, not proof that an attacker is present. Every finding in this tool lists a possible benign explanation, because in real SOCs most alerts turn out to be ordinary IT activity. The skill is ruling things in or out with evidence.

          Why severity is not certainty

          Severity here means investigative priority: how soon an analyst might want to look. A High finding can be benign and a Low one can be the first sign of something serious. The investigation score simply adds up the points shown, so you can see exactly why something ranks where it does. It is an educational prioritisation mechanism, not a mathematical probability of compromise.

          Absence is not evidence

          If an event is missing, that does not prove the activity did not happen. Auditing may be switched off, or the log may have been cleared or overwritten.

            Getting a CSV from Windows Event Viewer

            1. Open Event Viewer (press Windows key, type Event Viewer, run it as administrator).
            2. Go to Windows Logs › Security.
            3. Optional: click Filter Current Log… and enter the IDs you want, for example 4624,4625,4720,4726,4728,4732,1102,4688.
            4. Click Save Filtered Log File As… (or Save All Events As…) and choose CSV (Comma Separated).
            5. Upload the CSV into this tool.

            To include PowerShell (4104) and service (7045) events too, create a Custom View covering the Security, System and Microsoft-Windows-PowerShell/Operational logs and save that as CSV. The README also shows a PowerShell command that exports the same events.

            Using a Mac? macOS has no Event Viewer and does not produce Windows Event IDs. Use the demo buttons above, or run Windows in a free virtual machine (for example UTM on Apple Silicon) and export the Security log from there. The README has step-by-step instructions.
